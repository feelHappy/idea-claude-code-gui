# 知识自动摄入规则

> 本规则定义 Agent 在日常开发中如何自动识别和沉淀经验。
> 对标 LLM Wiki 的 Ingest 操作——知识应该自动从交互中沉淀，而不是全靠人手动写。

---

## 触发时机

Agent 在以下时刻**主动评估**是否需要沉淀知识：

| 时机 | 评估内容 |
|------|---------|
| **编译/构建失败 ≥2 次**（同一问题） | 根因是否为可复用的坑？ |
| **方案变更**（推翻初始方案） | 为什么变？新方案的决策依据？ |
| **排查耗时 >20 分钟** | 排查路径中哪些是可复用的诊断经验？ |
| **会话 >5 轮** | 本次会话是否产生了新的模式/坑/决策？ |
| **快速修复完成后** | 虽然改动小，但如果踩了坑也值得记录 |

---

## 评估标准（满足任一即沉淀）

1. **可复用性**：其他模块/需求也可能遇到同样的问题
2. **非显而易见**：不是看文档就能知道的，需要踩过才知道
3. **有根因**：不只是"改了就好了"，而是理解了为什么
4. **有反模式**：明确了"不应该怎么做"

---

## 沉淀方式（按优先级）

### 1. 追加到已有 Playbook

如果问题属于已有 playbook 的领域，直接追加新条目：

```markdown
### 问题 N+1: [标题]

**现象**：...
**根因**：...
**处理**：...
**复用建议**：...
```

同时检查是否需要在 `index.md` 的"通用原则速查"中新增条目。

### 2. 新建 Playbook

如果问题属于全新领域（现有 playbook 都不匹配），按模板新建：
1. 复制 `.harness/templates/playbook-template.md` → `.harness/playbooks/{topic}.md`
2. 填写至少 2 个已确认的问题
3. 在 `index.md` 索引表和场景映射表中添加条目

### 3. 更新通用原则

如果发现了跨场景的黄金法则，直接追加到 `index.md` 的"通用原则速查"表。

---

## 不沉淀的情况

- 纯 typo / 配置遗漏 / import 缺失 — 太琐碎，无复用价值
- 已有 playbook 中已经覆盖的问题 — 不重复记录
- 一次性的业务逻辑调整 — 不具备通用性
- 外部依赖的临时 bug（等升级修复）— 不是自身经验

---

## 沉淀格式要求

- 每条记录必须包含：现象 → 根因 → 处理 → 复用建议
- 代码示例用 ✓/✗ 对比（正确做法 vs 错误做法）
- 标注来源 commit hash（便于追溯）
- 不写"可能是"/"也许"——只记录已确认的事实

---

## Lint 检查（定期维护）

每 5 次会话或用户主动触发时，执行知识库健康检查：

1. **路径有效性**：playbook 中引用的文件路径是否仍然存在？
2. **规范一致性**：rules 中的编码规范是否与最新代码一致？
3. **Skill 可达性**：skills/index.md 中列出的 skill 路径是否都可访问？
4. **时效性**：是否有 playbook 超过 3 个月未更新？标记 `[stale]`
5. **覆盖度**：最近 5 次会话中踩的坑，是否都有对应 playbook 覆盖？

检查结果输出为简表，只报告异常项。全部正常时静默。
