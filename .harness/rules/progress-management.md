# 进度管理规则

> **所有开发工作都需要追踪**，不区分快速通道和完整流程。
> Agent 在**任何开发任务开始时**都必须执行本规则。

---

## 核心原则

**所有改动都值得记录**。一次"小调整"可能花一上午，跨会话后完全遗忘。进度追踪的成本极低（追加几行 Markdown），但跨会话恢复的价值极高。

---

## 进度日志（所有任务通用）

### 位置

```
_bmad-output/planning/{需求编号}/progress.md
```

### 触发时机（强制）

以下任一条件满足时，**必须**追加一条进度记录：

1. **会话开始时**：记录本次会话的目标（一句话）
2. **完成一个逻辑单元后**：一个方法、一组关联文件、一个 bug 修复
3. **构建通过后**：记录本次改了什么
4. **遇到阻塞/方案变更时**：记录卡点和决策
5. **会话结束前**：记录当前进度和下一步

### 格式

```markdown
## [YYYY-MM-DD] 会话目标简述

- [完成] 具体做了什么（涉及哪些文件）
- [完成] 第二项改动
- [阻塞] 遇到什么问题，如何解决的
- [下一步] 还剩什么没做

变更文件：
- `path/to/File1.java` — 改动说明
- `path/to/File2.java` — 改动说明
```

### 快速通道 vs 完整流程

| 路径 | 追踪方式 |
|------|---------|
| **快速通道**（≤2 文件的小改动） | 追加到 `progress.md`，不需要 summary.md |
| **完整流程**（新功能/多文件） | `summary.md`（八阶段状态机）+ `progress.md`（细节日志） |

---

## 进度快照（完整流程专用）

### 位置

```
_bmad-output/planning/{需求编号}/summary.md
```

### 用途

- 八阶段流水线的状态机记录
- 跨会话恢复时的 Single Source of Truth
- 每个阶段完成后立即更新

---

## 冷启动序列（新会话恢复未完成需求）

```
1. 读取 progress.md（最近的记录）
2. 如果有 summary.md → 读取，定位最后完成阶段
3. 从下一步继续
4. 都不存在 → 新需求，从头开始
```

---

## 多需求并行开发

- 每个需求独立维护 progress.md
- 共享文件串行修改，私有文件可并行
- 需要改共享表/接口时，在 progress.md 标注 `[Data Contract Change]`
